\section{Fundamentação Teórica} \label{sec:firstpage}
\subsection{Computação Paralela}
Do período de 1986 até 2002, o desempenho dos processadores aumentava cerca de 52\% a cada ano \citep{herlihy2008}. No entanto, desde 2002 o crescimento de desempenho das novas gerações de microprocessadores tem desacelerado cada vez mais, isso se deve ao limite físico do silício \citep{hennessy2017}. Desse modo, por volta de 2005, a grande maioria das fabricantes de microprocessadores decidiu que o caminho para o ganho de desempenho estava direcionado à programação paralela \citep{pacheco2011}.
\par
\citep{pacheco2011} aponta que na computação paralela "um programa é aquele no qual múltiplas tarefas cooperam intimamente para resolver um problema". Nesse sentido, operações matriciais representam um problema adequado para o paralelismo, já que o cálculo de elementos diferentes podem ser distribuídos em diferentes unidades de execução.

O paralelismo de dados está relacionado a distribuição de subconjuntos de um mesmo dado entre multíplos processadores. Já o paralelismo de tarefas envolve a distribuição de \textit{threads} entre os núcleos. \cite{silberschatz2018}. Nesse sentido, o problema clássico da  multiplicação de matrizes é explorado como um problema de paralelismo de dados, uma vez que diferentes elementos da matriz resultante podem ser calculados de maneira independente.

\subsection{Multiplicação de Matrizes}
De acordo com \cite{cormen2012}, o problema clássico para multiplicação de matrizes envolve duas matrizes dadas, A e B, e C uma nova matriz a ser calculada. A operação que define cada elemento $C_{ij}$ pode ser dada como:
\begin{equation}
C_{ij} = \sum_{k=1}^{n} A_{ik}B_{kj}
\end{equation}
\par
Ou seja, cada elemento $C_{ij}$ é obtido pelo produto escalar entre a linha $i$
de A e a coluna $j$ de B. Dessa forma, o algoritmo sequencial possui um custo $O(n^3)$ para matrizes de dimensão N por N. 
\subsection{Vetorização}
Segundo \cite{allen2002} vetorização foi uma das técnicas que permitiram com que resultados ideais em diversas arquiteturas paralelas ocorresem para multiplicação de matrizes. A vetorização é uma técnica que permite explorar o paralelismo a nível de dados por meio de instruções SIMD (\textit{Single Instruction, Multiple Data}), ou seja, operação de múltiplos dados sobre a mesma instrução \cite{hennessy2017}. 
\par
Na vetorização automática o compilador identifica trechos específicos do código como laços de repetição, em que as operações podem ser realizadas de forma paralela em nível de instrução, e os transformam em instruções vetoriais compatíveis com os recursos do processador. Dessa forma, é possível reduzir o número de instruções para processar um conjunto de dados, melhorando o tempo de execução de programas, permitindo com que a multiplicação de matrizes seja executado em tempo ideal \cite{intel2023vectorization}. 

\subsection{Princípio da localidade espacial}
\cite{hennessy2017} mostram que segundo o princípio da localidade espacial, quando um dado é acessado, existe uma grande possibilidade dos dados armazenados próximos serem necessários. Dessa forma, quando um dado não é encontrado em \textit{cache}, o processador busca um bloco de dados próximos ao dado na memória principal.
\par
Nesse sentido, segundo \cite{cppreference_array}, em C/C++ as matrizes multidimensionais são armazenadas em ordem \textit{row-major}, ou seja, os elementos de uma mesma linha ocupam posições consecutivas na memória. Por conseguinte, percorrer os elementos de uma linha de forma consecutiva, tende a favorecer a localidade espacial, já percorrer por coluna desfavorece o aproveitamento de dados em \textit{cache}.
\subsection{Transposição de matrizes}
\par
No cenário de multiplicação de matrizes o acesso à memória da matriz B terá um custo maior que A. Assim, a transposição da matriz, definido por \cite{cormen2012} como a permutação dos elementos de cada i-ésima linha, pela j-ésima coluna, pode resolver o problema do armazenamento na memória, alterando apenas a forma de cálculo da matriz C para manter o resultado, computando com os elementos da linha "$j$" ao invés da coluna. 

\subsection{Algoritmo de Strassen para multiplicação de matrizes}
Segundo \cite{ikenmeyer2019strassen} o algoritmo de Strassen para multiplicação de matrizes foi uma descoberta revolucionária na álgebra linear computacional. A ideia central desse algoritmo é multiplicar matrizes de tamanho 2X2 com apenas 7 operações, utilizando a estratégia de divisão e conquista aplicar a matrizes N x N. O algoritmo surge da decomposição da forma: 
\begin{equation}
XY = \sum_{k=1}^{7} u_{k}(X)v_{k}(Y)W_{k}
\end{equation}
\par
Em que $u_k$ e $v_k$ são formas lineares escolhidas no espaço das matrizes 2X2 e $W_k$ são sete matrizes de tamanho 2X2. Aplicando esse algoritmo é possível reduzir o custo computacional para $O(n^{\log_{2}7})$ operações aritméticas \cite{ikenmeyer2019strassen}.

\subsection{Métricas de Desempenho}
 Entre as principais métricas para avaliação do desempenho de algoritmos destacam-se: Tempo de execução; \textit{Overhead} paralelo total; \textit{Speedup}; Eficiência;
\par
\cite{grama2003} definem o tempo de execução de um algoritmo sequencial $T_s$ como o tempo decorrido entre o início e o fim de sua execução em um computador sequencial. Já o tempo de execução de um algoritmo paralelo $T_p$ é definido como o tempo decorrido a partir do momento em que a computação paralela se inicia até o momento da execução do último elemento de processamento.
\par
Os custos computacionais adicionados devido à paralelização são encapsulados em uma expressão chamada \textit{overhead}, que pode ser definida como o tempo total gasto por todos elementos coletivamente, além do tempo necessário pelo algoritmo sequencial \cite{grama2003}. Dessa forma, sendo $p$ o número de \textit{threads} \textit{overhead} paralelo total pode ser calculado como:
\begin{equation}
T_o = pT_p - T_s
\end{equation}
\par
\textit{Speedup} é a medida que mostra o benefício relativo de programar paralelamente em relação ao programa sequencial \cite{grama2003}. Assim, o \textit{Speedup} do sistema pode ser calculado como a razão do tempo de execução sequencial pelo tempo em paralelo como na equação abaixo:  
\begin{equation}
S_p = \frac{T_s}{T_p}
\end{equation}
\par
Já a eficiência é uma medida da fração de tempo na qual um elemento de processamento está utilmente empregado \cite{grama2003}. A eficiência pode ser calculada como:
\begin{equation}
E_p = \frac{T_s}{pT_p}.
\end{equation}


\section{Trabalhos Relacionados}

\subsection{Parallel matrix transpose algorithms on distributed memory concurrent computers}

\par O artigo “Parallel matrix transpose algorithms on distributed memory concurrent computers” \cite{art1} trata da criação de um algorítimo referente à realização de operações de transposição de matrizes utilizando-se de computação paralela.
\par Para realizar o procedimento, o algoritimo separa os processadores disponíveis em uma matriz de duas dimensões e, utilizando distribuição de dados bloco-cíclica (block cyclic data distribution), divide sub-seções da matriz a serem analisadas por processadores específicos. 
\par Dependendo da divisão dos processadores na representação 2D, sendo P o número de linhas e Q o número de colunas, duas situações distintas podem ocorrer: o máximo divisor comum (MDC) entre P e Q é calculado. Caso ele seja igual a 1, os números são matematicamente primos, e todos os processadores precisam realizar os procedimentos realizando ‘comunicação total’ entre si. 
\par Caso o MDC seja maior que 1, o algorítimo divide os blocos de processadores em grupos delimitados pelo MDC, nos quais todas as operações de transposição entre blocos de mesmo grupo podem ocorrer simultaneamente, diminuindo a quantidade total de tempo de execução.
\par A análise final do algorítimo realizada no artigo demonstra que, em uma múltiplicação de matrizes, transpor o resultado da operação utilizando o processo descrito aumenta em pouco o tempo total de execução. Ademais, o algoritimo se destaca, em principal, ao suportar versatilidade quanto a proporções em grades bidimensionais não quadradas (com P diferente de Q), não só mantendo alta eficiência, mas superando algoritimos restritos a arranjos quadrados.
\par Um ponto negativo observável no algoritimo, no entanto, possui uma descrição breve no artigo em si. Quando P e Q tem MDC igual a 1 e a comunicação total é realizada, a sua implementação é não só mais lenta do que o método com MDC maior, mas também não se utiliza da melhor implementação possível em teoria. Os autores optam por uma implementação não óptima que, dada a quantidade arbtirariamente grande de processadores, seria mais simples de ser utilizada.

\subsection{Anatomy of High-Performance Matrix Multiplication}
\par Outro artigo mais diretamente relacionado ao tópico é “Anatomy of High-Performance Matrix Multiplication” \cite{art2}, que discorre diretamente sobre implementações otimizadas de operações de multiplicação de matriz, mais especificamente sobre gerenciar de maneira eficiente a hierarquia de memória disponível para obter alto desempenho de maneira consistente.
\par Os autores identificam que, nas abordagens mais tradicionais, os algoritimos criados não condizem às capacidades reais do hardware ao mensurar performance, como o número finito de entradas no Translation Look-aside Buffer (TLB) e as latências das memórias cache. O algorítimo proposto, portanto, busca segmentar mais o problema utilizando empacotamento a fim de aproveitar mais a memória no nível local.
\par Para evitar os gargalos de memória descritos, o sistema proposto reestrutura o algoritimo comum da GEMM (General Matriz Multiplication) em níveis distintos: no mais alto nível, a matriz de entrada é particionada de modo que o painel da matriz A é dimensionado para se ajustar ao cache L2 (ou L3) e ao limite de entradas do TLB, enquanto os blocos da matriz B são empacotados para fluir diretamente pelo cache L1.
\par Em nível de bloco, os dados lhe atribuídos passam pelo processo de empacotamento, a partir do qual os pacotes são inseridos em buffers temporários contíguos, para que o acesso a eles possa ser mais rápido e direto no processamento.
\par No micro-kernel, o processamento é realizado em pequenas submatrizes, maximizando a instrução vetorial e o paralelismo ao nível de instrução, O artigo apresenta variados experimentos que demonstram o aumento de desempenho dado por sua abordagem, e é uma base fundamental para análise referente às operações fundamentais de GEMM, e o algorítimo é utilizado em múltiplas bibliotecas atuais de computação de alta performance (HPC), como OpenBLAS  e Intel MKL.
\par Apesar da alta eficiência do procedimento, um ponto negativo observável é que o processo é bastante elaborado e, portanto, contém overhead significativo. Dado que os procedimentos buscam utilizar o máximo possível de performance, o algoritimo é projetado para uma quantidade grande de processamento necessário e, caso a operação seja simples, as soluções implementadas seriam mais custosas do que óptimas em totalidade.

\subsection{Relação com o Projeto Principal}
\par Os artigos descritos, para o propósito deste projeto, apresentam não apenas algoritmos eficientes em suas respectivas áreas de ênfase (transposição e multiplicação de matrizes), mas também demonstram, ao longo de suas análises, diversas estratégias de gerenciamento de recursos do sistema para otimizar processos dependentes de matrizes. Dessa forma, mesmo que o presente trabalho não consista em uma reconstrução direta de nenhum dos métodos, ambos os artigos contêm esquemas de particionamento e análise bastante úteis para o desenvolvimento de nosso projeto.

\subsection{Método de Strassen}
\par A segunda implementação escolhida para os testes foi o algoritmo de Strassen para multiplicação de matrizes. Esse algoritmo foi escolhido pois possui algumas propriedades que tornam sua paralelização um caso interessante. Como discutido anteriormente na fundamentação, esse algoritmo efetua multiplicações em matrizes 2x2 utilizando somente 7 operações, isso é interessante devido a essas operações serem independentes entre si, possibilitando a paralelização de sua execução para verificação da eficiência.
\par As métricas de desempenho utilizadas nessa implementação são as mesmas vistas anteriormente, tempo de execução tanto sequencial quando paralelo, \textit{overhead} paralelo total, \textit{speedup} e eficiência.
\par O código foi implementado na linguagem C e utiliza o OpenMP para efetuar sua paralelização. \textit{Multithreading} é utilizado para realizar as operações de soma e subtração de matrizes existentes no método de Strassen. Entretanto, algumas restrições foram implementadas para impedir que o custo de gerenciar todas as tarefas existentes não supere o ganho do paralelismo. Como o método de Strassen utiliza recursão, a criação desregulada de tarefas pode rapidamente diminuir a eficiência do programa, por conta disso, uma restrição foi colocada para que novas tarefas sejam criadas somente quando a matriz sendo computada seja de um certo tamanho.
\par As matrizes utilizadas são geradas de maneira aleatória com dimensão N x N determinada em tempo de execução e cada elemento é povoado com um valor aleatório do tipo \textit{int} com valor variando entre -1000 e 1000.
